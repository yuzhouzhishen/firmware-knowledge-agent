# ESP-IDF Wi-Fi 事件与重连

## 事件驱动模型

ESP-IDF Wi-Fi 驱动通过事件循环通知应用状态变化。应用应区分 Wi-Fi 已启动、STA 已连接、STA 已断开和获得 IP 等事件，而不是只根据调用 `esp_wifi_connect()` 的返回值判断网络已经可用。

建立 AP 连接和获得 IP 是不同阶段。依赖 TCP、HTTP 或 MQTT 的业务通常应在获得 IP 后启动，并在断开时停止或重建相关连接。

## 断线重连

一次 `esp_wifi_connect()` 只发起一次连接尝试。应用可以使用配置中的失败重试能力，也可以在断开事件中实现受控重连。

重连逻辑应设置最大次数、退避和状态标记。主动调用 `esp_wifi_disconnect()` 产生的断开事件不应该无条件触发重连，否则会与用户主动断开意图冲突。

## 故障排查

排查时同时记录断开原因、重试次数、信号强度和是否获得 IP。只看到“STA connected”不能证明 DNS、路由和上层 socket 已经可用。
